## Environment quirks (important)

- **Ollama provider**: `ollama-cloud` is served by pi's default path via
  `~/.pi/agent/models.json` (20 models, key read with `!command`). The integration
  `~/.local/share/pi-integrations/index.ts` **skips** that pool via
  `providerManagedByModelsJson: true` in `~/.config/pi-account-pool/accounts.json`.
  Do not re-register it through the pool; doing so caused `400 failed to read request body`
  (missing `streamSimple` shaping) and `account_pool_exhausted` with many agents.
- **Alibaba DeepSeek pools** still go through the pool wrapper (that is wanted).
- Backups: `index.ts.bak-pool`, `accounts.json.bak`.
- Device: ONN TV `192.168.88.30:5555` (1920x1080). Phone emulator profile
  `viptv-design-phone` (start **headless**; the Qt/xcb path fails on this host).
- **`adb screencap` returns black for the video surface** — never treat a black
  capture as a black picture. Judge playback from Media3 callbacks / the owner.
- Desktop: the virtual display has **no GL**; use `SKIKO_RENDER_API=SOFTWARE` there.
  The physical `:0` display is the user's session (capturing it grabs their game).
