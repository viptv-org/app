# Profile administration audit — 2026-10-15

Existing local and remote create/name/avatar/delete APIs remain in use. Local profile PINs remain distinct from server household parent grants, and primary/last-profile deletion remains subject to existing host rules. No new API or native binding was introduced.

Profile mutation handlers now ignore duplicate or competing submissions while an operation is busy. A repeated stale UI action no longer cancels an already submitted create/rename/avatar/delete/PIN operation and sends another mutation. Profile selection and unlock submission use the same busy gate. A remote per-profile PIN call now explains the actual account parent-PIN contract instead of reporting an invalid HTTPS address.

Name/avatar/delete dialogs require a local PIN only when a local profile lock is actually supported. A remote parent-locked profile no longer prompts for a local PIN that its transport would ignore. Server parent authorization remains authoritative; removing that unrelated input does not grant access or bypass server policy. Local lock dialogs still require the existing 4–8-digit PIN.

The profile edit Language row now says Audio & subtitles and describes supported playback languages. It does not promise per-profile menu localization. Its guidance uses the existing Subtitles & audio settings section. If the edited profile is not selected, the action returns to profile selection and explicitly asks the user to choose it; it never changes a different profile's preferences or silently switches scope. Maturity guidance uses the existing Parental controls section: local maturity filtering remains unsupported, while remote household restrictions belong to server policy/account parent PINs. Native clients retain the existing validated server-dashboard path; browser clients retain the existing in-app household forms.

The optional settings section entry is cleared by ordinary navigation, so later settings visits do not inherit a stale profile-edit destination. TV maps the same supported section IDs to its existing sidebar, and existing remote rating labels are presented only when supplied by profile management. Profile preferences still round-trip all existing audio/subtitle/source/quality/style fields.
