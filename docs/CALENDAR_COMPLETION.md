# Connected calendar completion — 2026-10-15

The real KMP calendar now exposes the existing server schedule categories (TV, Anime, Movies), previous/this/next week controls, the selected date range, and explicit release actions. It retains the supplied date-rail/list/preview design and existing navigation. Empty dates remain selectable on TV, desktop and phone. Phone groups include empty-day anchors so selecting one can actually scroll to it; desktop and TV show a clear empty-day message.

## Authority and request bounds

`/api/v3/calendar` already supplies an origin-bearing parent Card, date, and separate season/episode hints. Those hints are retained numerically in CalendarEntry; they are not parsed back out of presentation text or converted into fabricated IDs. Each visible week requests its seven local days with the existing UTC boundary margin. Category/week changes cancel and fence previous progressive results. Initial requests remain 100 entries followed by server cursors in pages of 500, with no per-release metadata/source/tracking fan-out. Week movement is bounded to 52 weeks each direction; it filters the provider's available schedule, without promising historical/archive data.

A remote 422 calendar availability response becomes an explicit unavailable state with Manage integrations. Other errors and authentication failures retain their normal handling. Local mode remains unavailable. No additional discovery-control request was introduced just to detect availability.

Past releases with a Simkl metadata origin can offer Find sources (movie) or Find Sx Ey (an explicit scheduled episode). The action opens Details, fetches current metadata using the original parent/origin/assertions, and selects only an actual returned Card with exactly matching aired-order season/episode, parent and origin. Metadata season offsets select bounded targeted pages. The operation is capped at the initial page plus three targeted pages under an eight-second timeout. The source picker receives that actual Card and its original provider ID; no episode ID is synthesized and no first-episode fallback is used. Navigation/profile/replacement cancellation prevents a late result from starting sources.

Missing, duplicate, unsupported or unmapped anime coordinates remain in Details with an explanation and the normal manual episode selection. Anime calendar numbers are not guessed into absolute/TVDB order. A scheduled release or a past timestamp does not guarantee that a stream is available; Find sources performs the normal source discovery and policy checks. Backend contracts and native bindings were not changed for this feature.

## Verification

The focused gate passed **11 tests** (CalendarActionsTest 5, CalendarControlsUiTest 3, RemoteCalendarTest 3), plus Wasm compilation and Android Kotlin compilation, in 29 seconds. It used final existing engines with engine rebuilds skipped, Gradle workers 2, and did not write the live/default Wasm distribution.

Controller/transport cases prove exact returned episode selection through a season offset, preservation of numeric hints, category/week requests, 422 availability, ambiguity and unmapped-order fallback, late-navigation isolation, and the four-request metadata ceiling. Existing progressive-page/cursor/cancellation cases remain green. Actual Compose rendering checks TV/phone/desktop actions, all date controls including empty dates, and release focus retained as later rows arrive. The initial direct-row focus probe was corrected to enter through the selected date, matching the intentional date-first focus contract; no production focus behavior was weakened to pass the test.
